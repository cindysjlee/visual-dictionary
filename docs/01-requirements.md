# 요구사항 명세: 보안·CS 개념 시각화 사전

## 1. 개요

| 항목 | 내용 |
|---|---|
| 서비스명 | 보안·CS 개념 시각화 사전 (가칭) |
| SW 종류 | 웹서비스 |
| 목적 | XSS, CSRF, SQL 인젝션 등 보안 공격 기법과 콜 스택, 데드락, TCP 3-way 핸드셰이크 등 CS 개념을 단계별 애니메이션으로 보여주어 쉽게 이해하도록 돕는다 |
| 대상 사용자 | 보안·CS를 학습하는 학생 및 입문 개발자 |
| 핵심 가치 | 공격이 "어떻게 진행되는지"와 "어디서 막히는지"를 눈으로 확인하고, 자신의 학습 진행 상황을 관리할 수 있다 |

사용자는 로그인 없이도 모든 용어를 찾아보고 애니메이션을 볼 수 있다. 회원가입 후 로그인하면 어떤 용어를 학습했고 어떤 용어가 남았는지 저장되어, 다른 기기에서도 이어서 학습할 수 있다.

## 2. 서브시스템 구성

서비스가 제공하는 기능을 사용자 관점의 기능군으로 묶고, 각 기능군을 하나의 서브시스템으로 정의한다.

| ID | 서브시스템 | 책임 |
|---|---|---|
| SS-01 | 용어 탐색 | 용어 목록 표시, 카테고리 필터, 키워드 검색, 상세 페이지 진입 |
| SS-02 | 용어 상세 조회 | 상세 페이지 구성 및 개념 설명·방어 방법·참고 자료 표시 |
| SS-03 | 애니메이션 재생 | 시나리오 데이터 기반 애니메이션 재생, 재생 제어, 자막 동기화, 방어 모드 |
| SS-04 | 사용자 인증 | 회원가입, 로그인·로그아웃, 비밀번호 재설정, 회원 탈퇴 |
| SS-05 | 학습 진행 관리 | 용어별 읽음 상태 기록·변경, 진행률 표시, 읽음 상태 필터 |
| SS-06 | 콘텐츠 관리 | 용어 시나리오 데이터의 형식 정의·검증, 목록·검색 인덱스 생성 |
| SS-07 | 배포·운영 | 프론트엔드 및 API 배포, HTTPS 제공, 라우팅 처리, 보안 헤더 적용 |

## 3. 기능 요구사항

우선순위: **필수**(1차 출시 포함), **선택**(1차 출시 이후)

### SS-01 용어 탐색

| ID | 요구사항명 | 상세 내용 | 우선순위 |
|---|---|---|---|
| FR-EXP-01 | 용어 목록 표시 | 홈 화면에 전체 용어를 카드 형태로 표시한다. 카드에는 용어 이름, 한 줄 요약, 카테고리 배지가 포함된다. | 필수 |
| FR-EXP-02 | 카테고리 필터 | 카테고리(웹 보안, 네트워크, 운영체제, 자료구조/런타임 등) 탭을 제공하고, 선택한 카테고리의 용어만 표시한다. "전체" 탭을 기본값으로 한다. | 필수 |
| FR-EXP-03 | 키워드 검색 | 용어 이름(한글·영문), 별칭, 요약을 대상으로 검색한다. 입력 즉시 결과가 갱신되며 대소문자를 구분하지 않는다. 카테고리 필터와 함께 적용된다. | 필수 |
| FR-EXP-04 | 검색 결과 없음 안내 | 검색 결과가 없으면 안내 문구와 함께 전체 목록으로 돌아가는 버튼을 표시한다. | 필수 |
| FR-EXP-05 | 상세 페이지 진입 | 카드를 선택하면 해당 용어의 상세 페이지로 이동한다. 각 용어는 고유 URL(`/terms/{id}`)을 가지며 URL로 직접 접근할 수 있다. | 필수 |

### SS-02 용어 상세 조회

| ID | 요구사항명 | 상세 내용 | 우선순위 |
|---|---|---|---|
| FR-DTL-01 | 상세 페이지 구성 | 용어 이름 → 개념 설명 → 애니메이션 → 단계별 자막 → 방어 방법 → 참고 자료 순으로 구성한다. | 필수 |
| FR-DTL-02 | 방어 방법 표시 | 보안 용어는 대표 방어 기법의 이름과 설명을 표시한다. CS 용어는 해당 섹션을 "해결 방법"(예: 데드락 회피)으로 대체하거나 생략한다. | 필수 |
| FR-DTL-03 | 참고 자료 표시 | 콘텐츠의 근거가 된 출처(예: OWASP 문서)를 표시한다. | 필수 |
| FR-DTL-04 | 잘못된 용어 접근 처리 | 존재하지 않는 용어 ID로 접근하면 안내 문구와 목록으로 이동하는 버튼을 표시한다. | 필수 |
| FR-DTL-05 | 관련 용어 연결 | 관련 용어(예: XSS → 세션 하이재킹) 링크를 표시한다. | 선택 |

### SS-03 애니메이션 재생

| ID | 요구사항명 | 상세 내용 | 우선순위 |
|---|---|---|---|
| FR-ANI-01 | 재생 시작 | 상세 페이지 진입 시 1단계에서 정지 상태로 시작하고 무대 가운데에 재생 버튼을 보여준다(설명을 먼저 읽을 수 있게). 재생을 시작하면 마지막 단계까지 이어서 재생하며, 단계 사이 대기 시간은 자막을 다 읽을 수 있게 자막 길이에 비례한다. 모드를 바꾸면 1단계로 가되 재생 상태는 유지한다. | 필수 |
| FR-ANI-02 | 행위자 표시 | 시나리오에 정의된 행위자(사용자, 공격자, 서버, DB 등)를 화면에 배치하며, 역할별로 모양과 색상을 구분한다. | 필수 |
| FR-ANI-03 | 단계별 동작 표현 | 각 단계에서 행위자 간 메시지(요청·응답·데이터)의 이동을 표현하고, 위험 단계는 경고 색상으로 강조한다. | 필수 |
| FR-ANI-04 | 재생 제어 | 재생/일시정지, 이전 단계, 다음 단계, 다시 보기 버튼을 제공한다. 다시 보기는 1단계부터 재생한다. | 필수 |
| FR-ANI-05 | 자막 동기화 | 현재 재생 중인 단계의 설명 자막을 표시하고, 전체 단계 중 현재 위치(예: 3/6)를 표시한다. | 필수 |
| FR-ANI-06 | 방어 모드 | 방어 모드 토글을 켜면 같은 시나리오를 재생하되, 지정된 단계에서 공격이 차단되는 연출과 방어 자막을 보여준다. | 필수 |
| FR-ANI-07 | 플레이어 유형 | 시나리오 데이터의 유형 값에 따라 메시지 흐름형(보안, TCP), 스택형(콜 스택), 자원 점유형(데드락) 플레이어 중 하나를 사용한다. | 필수 |
| FR-ANI-08 | 재생 속도 조절 | 0.5배, 1배, 1.5배 속도를 선택할 수 있다. | 선택 |

### SS-04 사용자 인증

| ID | 요구사항명 | 상세 내용 | 우선순위 |
|---|---|---|---|
| FR-AUTH-01 | 비회원 이용 | 로그인하지 않아도 모든 용어의 탐색·조회·애니메이션 재생이 가능하다. 학습 진행 기능을 사용하려 하면 로그인을 안내한다. | 필수 |
| FR-AUTH-02 | 회원가입 | 이메일과 비밀번호로 가입한다. 비밀번호는 8자 이상이며 영문과 숫자를 포함해야 한다. 이메일로 발송된 인증 코드를 입력해야 가입이 완료된다. 이미 가입된 이메일은 가입할 수 없다. | 필수 |
| FR-AUTH-03 | 로그인·로그아웃 | 이메일과 비밀번호로 로그인하며, 로그인 상태는 브라우저를 닫았다 열어도 일정 기간 유지된다. 로그아웃 시 저장된 인증 정보를 삭제한다. | 필수 |
| FR-AUTH-04 | 로그인 상태 표시 | 화면 상단에 로그인 상태에 따라 로그인 버튼 또는 사용자 메뉴(진행 현황, 로그아웃, 계정 설정)를 표시한다. | 필수 |
| FR-AUTH-05 | 비밀번호 재설정 | 비밀번호를 잊은 경우 가입한 이메일로 인증 코드를 받아 새 비밀번호를 설정한다. | 필수 |
| FR-AUTH-06 | 회원 탈퇴 | 사용자가 탈퇴하면 계정과 해당 사용자의 학습 기록을 모두 삭제한다. 탈퇴 전 확인 절차를 거친다. | 필수 |
| FR-AUTH-07 | 소셜 로그인(Google) | Google 계정으로 가입·로그인할 수 있다. 같은 이메일이라도 Google 계정과 이메일 가입 계정은 서로 다른 계정이며, 학습 기록도 따로 저장된다. 로그인·가입 화면에 이를 안내한다. 로그아웃하면 이 서비스의 인증 정보를 삭제한다(Google 계정 로그인 상태는 유지). | 선택 |
| FR-AUTH-08 | 탈퇴 재확인 | 탈퇴 전에 본인임을 다시 확인한다: 이메일 사용자는 비밀번호, Google 사용자는 Google 계정 선택을 다시 거친다. 서버는 최근 5분 안에 인증한 경우에만 탈퇴를 처리한다(화면을 거치지 않고 API를 직접 불러도 같다). 확인 뒤 절차는 FR-AUTH-06과 같다. | 필수 |
| FR-AUTH-09 | 개인정보처리방침 | 처리하는 정보, 이용 목적, 보관 기간, 제3자 제공, 처리 위탁, 이용자 권리, 문의처를 `/privacy`에 공개하고 푸터와 로그인·가입 화면에서 연결한다. | 필수 |

### SS-05 학습 진행 관리

| ID | 요구사항명 | 상세 내용 | 우선순위 |
|---|---|---|---|
| FR-PRG-01 | 학습 완료 자동 기록 | 로그인한 사용자가 애니메이션을 마지막 단계까지 재생하면 해당 용어를 "읽음"으로 기록한다. 기록은 서버에 저장되어 다른 기기에서 로그인해도 유지된다. | 필수 |
| FR-PRG-02 | 읽음 상태 직접 변경 | 상세 페이지에서 "읽음/안 읽음"을 직접 전환할 수 있다. 다시 복습하고 싶은 용어는 안 읽음으로 되돌릴 수 있다. | 필수 |
| FR-PRG-03 | 목록 내 상태 표시 | 로그인 상태에서 용어 목록의 각 카드에 읽음 여부를 표시한다. | 필수 |
| FR-PRG-04 | 읽음 상태 필터 | 목록에서 전체/읽음/안 읽음 필터를 제공하며, 카테고리 필터 및 검색과 함께 적용된다. | 필수 |
| FR-PRG-05 | 진행률 표시 | 전체 및 카테고리별로 읽은 용어 수와 전체 용어 수(예: 웹 보안 3/5)를 표시한다. | 필수 |
| FR-PRG-06 | 이어서 보기 | 최근에 본 용어 목록을 홈 화면에 표시한다. | 선택 |
| FR-PRG-07 | 비회원 기록 이전 | 비회원 상태에서 브라우저에 임시 저장한 읽음 기록을 로그인 시 계정으로 옮길지 선택할 수 있다. | 선택 |

### SS-06 콘텐츠 관리

| ID | 요구사항명 | 상세 내용 | 우선순위 |
|---|---|---|---|
| FR-CNT-01 | 용어 데이터 파일 | 용어 하나는 데이터 파일(JSON) 하나로 정의한다. 파일에는 ID, 이름, 별칭, 카테고리, 요약, 설명, 플레이어 유형, 행위자, 단계 목록, 방어 정보, 참고 자료가 포함된다. | 필수 |
| FR-CNT-02 | 스키마 검증 | 빌드 시 모든 데이터 파일의 형식을 검증한다. 필수 항목 누락, 정의되지 않은 행위자 참조, 범위를 벗어난 차단 단계 번호 등이 있으면 빌드를 중단하고 파일명과 오류 위치를 출력한다. | 필수 |
| FR-CNT-03 | 인덱스 자동 생성 | 빌드 시 데이터 파일로부터 목록·카테고리·검색용 인덱스를 자동 생성한다. 용어 추가 시 화면 코드 수정이 필요 없어야 한다. | 필수 |
| FR-CNT-04 | 검수 상태 관리 | 데이터 파일에 검수 완료 여부 항목을 두고, 검수되지 않은 용어는 배포 빌드에서 제외한다. | 필수 |
| FR-CNT-05 | 용어 ID 불변 | 한 번 배포된 용어의 ID는 변경하지 않는다. 학습 기록이 용어 ID를 기준으로 저장되기 때문이다. 삭제된 용어의 학습 기록은 진행률 계산에서 제외한다. | 필수 |

### SS-07 배포·운영

| ID | 요구사항명 | 상세 내용 | 우선순위 |

## 4. 비기능 요구사항

| ID | 분류 | 요구사항 | 검증 방법 |
|---|---|---|---|
| NFR-01 | 보안 | 모든 통신은 HTTPS로만 이루어진다. 비밀번호는 서비스가 직접 저장하지 않고 인증 서비스(Cognito)에 위임한다. API는 토큰의 사용자 정보로만 대상을 결정하여, 사용자는 본인의 학습 기록만 조회·수정할 수 있다. 수집하는 개인정보는 이메일로 한정한다. 검색어 등 사용자 입력은 HTML로 해석되지 않으며 CSP로 허용되지 않은 스크립트 실행을 차단한다. | 다른 사용자의 ID를 넣은 요청이 거부되는지 확인, 토큰 없는 요청 거부 확인, 보안 헤더 점검 도구로 헤더 확인, 검색창에 스크립트 문자열 입력 테스트 |
| NFR-02 | 성능·가용성 | 첫 화면은 일반 데스크톱 환경에서 3초 이내에 표시되고, 학습 기록 조회·저장은 1초 이내에 응답한다. 학습 기록 저장에 실패하더라도 용어 조회와 애니메이션 재생은 정상 동작해야 한다. | Lighthouse 성능 점수 80점 이상, API 응답 시간 측정, API를 차단한 상태에서 상세 페이지 동작 확인 |
| NFR-03 | 사용성·접근성 | 360px(모바일)부터 1920px(데스크톱)까지 레이아웃이 깨지지 않는다. 동작 줄이기 설정을 존중하고, 애니메이션을 보지 않아도 단계별 자막만으로 개념을 이해할 수 있으며, 재생 컨트롤은 키보드로 조작할 수 있다. | 주요 해상도별 화면 확인, 동작 줄이기 설정 후 재생 확인, 키보드만으로 조작 테스트 |

## 5. 개발 제약사항

| ID | 분류 | 제약사항 |
|---|---|---|
| DC-01 | 프론트엔드 기술 | React로 구현하고, 애니메이션은 three.js + React Three Fiber의 실시간 3D로 한다. 단계 진행은 화면과 분리된 재생 엔진 하나가 정하고, 단계 안의 움직임은 프레임 기반 타임라인으로 만든다. 일반 UI의 움직임은 Framer Motion, CSS Animation은 장식 효과에만 사용한다. WebGL을 쓸 수 없으면 2D 단계 목록으로 대체한다. |
| DC-02 | 인프라·백엔드 | AWS 관리형 서비스로만 구성한다. 프론트엔드는 S3 + CloudFront, 인증은 Cognito, 학습 진행 API는 API Gateway + Lambda, 데이터 저장은 DynamoDB를 사용한다. 상시 운영 서버(EC2 등)는 두지 않으며, 운영 비용은 AWS 프리 티어 범위 내를 목표로 한다. |
| DC-03 | 콘텐츠 제작 방식 | 모든 용어 콘텐츠는 정의된 스키마의 데이터 파일로만 추가하며, 용어별 개별 애니메이션 코드는 작성하지 않는다(새 플레이어 유형 추가는 예외). AI로 생성한 데이터는 개념 정확성과 출처를 사람이 검수한 뒤 배포한다. |

## 7. 검토 의견

- **범위 위험**: 인증과 학습 진행 기능이 추가되면서 정적 사이트였던 구조에 백엔드가 생겼다. 핵심 가치는 시각화이므로, 개발은 SS-01~03·SS-06(콘텐츠와 재생)을 먼저 완성하고 SS-04~05(인증·진행)를 이어서 붙이는 순서로 진행한다. FR-AUTH-01(비회원 이용)을 필수로 둔 것도 인증 기능이 늦어지더라도 서비스의 핵심이 동작하도록 하기 위함이다.
- **"읽음"의 기준**: 페이지 방문만으로 읽음 처리하면 진행률이 의미를 잃으므로, 애니메이션을 끝까지 재생했을 때 자동 기록하고 사용자가 직접 수정할 수 있도록 정의하였다(FR-PRG-01, 02).
- **데이터 정합성**: 학습 기록이 용어 ID에 의존하므로 ID 불변 원칙(FR-CNT-05)을 두어 콘텐츠 수정이 학습 기록을 깨뜨리지 않도록 하였다.
- **개인정보 최소화**: 수집 항목을 이메일로 한정하고, 비밀번호 저장을 인증 서비스에 위임하며, 탈퇴 시 학습 기록까지 삭제하도록 하였다(NFR-01, FR-AUTH-06). Google 로그인도 이메일·이메일 인증 여부·계정 식별자만 저장하고, 처리 내용은 개인정보처리방침(FR-AUTH-09)에 공개한다.
- **콘텐츠 정확성**: AI 생성 콘텐츠의 오류 위험은 검수 상태 관리(FR-CNT-04)와 참고 자료 표시(FR-DTL-03)로 대응한다.
- **1차 출시 범위**: "필수" 요구사항 전체와 초기 콘텐츠 8개(보안: XSS, CSRF, SQL 인젝션, 세션 하이재킹, SSRF / CS: TCP 3-way 핸드셰이크, 콜 스택, 데드락)로 한다.
