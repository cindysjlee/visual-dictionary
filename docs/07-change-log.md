# 변경 이력

처음 제출한 설계(요구사항 명세·도메인 모델·아키텍처, 첫 커밋 `a31fb77`의 docs)에서 바뀐 것을 시간 순서로 정리한다. 결함을 고친 기록은 `08-defect-log.md`에 따로 있고, 여기서는 그 결함이 설계·요구사항을 바꾼 경우만 연결한다.

**근거와 표기**
- 근거: git 기록(커밋 87개, 2026-11-18 ~ 2026-11-21), docs·CLAUDE.md의 변경 내역, 개발 대화 기록(`~/.claude/projects`의 이 프로젝트 기록. 프로젝트가 OneDrive 경로에 있던 11-18 기록 포함, 읽기만 함).
- 날짜는 관련 커밋의 날짜(한국 시간)다. 커밋이 없는 결정은 대화 날짜를 쓰고 "(대화)"로 적는다.
- 승인 방식
  - **사용자 결정**: 사용자가 계획을 보고 직접 정했다.
  - **사용자 승인**: diff·변경 세트를 확인한 뒤 "승인"이라고 답했다(배포 승인 규칙, CLAUDE.md).
  - **사용자 지시**: 사용자가 바꾸라고 지시했다.
  - **사용자 검수**: 사용자가 자막·내용을 읽고 고칠 점을 지정했다.
- 영향 범위 약어: 요(요구사항) · 설(설계 문서) · 코(코드) · 테(테스트) · 인(인프라)
- 근거를 찾지 못한 칸은 "근거 없음"으로 적었다.
