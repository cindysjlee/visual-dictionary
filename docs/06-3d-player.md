# 3D 플레이어 설계

애니메이션 플레이어를 2D(SVG + Framer Motion)에서 **실시간 3D(three.js + React Three Fiber)** 로 바꾼다.
기준 시안: `docs/design/csrf-3d-prototype.html` (CSRF 한 편, 공격 흐름·방어 모드·자유 시점 포함).
시안은 CDN에서 three.js r128을 불러오는 단일 HTML이다. 브라우저로 열어 재생해 볼 수 있다. 코드는 동작 참고용이고, 그대로 옮기지 않는다.

## 1. 왜 3D인가 (지켜야 할 핵심)

3D를 "옆에서 본 일자 배치"로 쓰면 2D와 차이가 없다. 아래 세 가지가 3D를 쓰는 이유이고, 모든 용어 장면에서 유지한다.

1. **공간이 곧 개념이다.** 배치 자체가 설명이 되게 한다. 예: 사용자 쪽(브라우저)은 앞, 서버는 인터넷 너머 뒤쪽 섬. 같은 브라우저 상자 안에 두 탭과 쿠키 보관함이 있어서, 어느 탭이 보냈든 같은 쿠키가 붙는다는 게 보인다.
2. **카메라가 설명한다.** 단계마다 카메라가 필요한 곳(보관함, 함정 탭, 검문소)으로 이동하고 날아가는 요청을 따라간다. 사용자가 시점을 돌리는 건 "자유 시점"을 켰을 때만 된다.
3. **물체의 앞뒤·안쪽을 쓴다.** 탭을 뒤집어 숨은 폼을 보여주고, 검문소에서 봉투를 열어 내용물(쿠키, 토큰)을 꺼내 검사한다.

## 2. CSRF 장면 (시안 기준)

### 배치 (월드 좌표, 단위는 three.js 기본)

| 대상 | 위치 | 설명 |
| --- | --- | --- |
| 브라우저 | (0, 0, 2.2) | 유리 상자 6.0×3.0×2.8, 상단바, 바닥판 |
| 은행 탭 / 함정 탭 | 브라우저 안 x = -1.45 / +1.45 | 앞면·뒷면이 있는 패널. 함정 탭은 3단계에 생긴다 |
| 쿠키 보관함 | 브라우저 안 앞쪽 가운데 | 유리병. 쿠키가 들어가고 나온다 |
| 은행 서버 섬 | (-5, 0, -4.2) | 건물, 금고 문, 섬 앞쪽에 검문소(기둥 2개, 스캔 링, 차단봉) |
| 함정 사이트 서버 섬 | (5, 0, -4.2) | 어두운 탑, 공격색 줄무늬 |
| 공격자 섬 | (8.6, 0, 1.6) | 후드 인물 |
| 인터넷 | 바닥 점선 | 탭 ↔ 서버 연결선 |

### 단계별 연출과 카메라

| 단계 | 연출 | 카메라 |
| --- | --- | --- |
| 1 정상 로그인 | 은행 탭 → 검문소(차단봉 올라감) → 은행 | 은행 쪽 샷, 봉투 따라가기 |
| 2 세션 쿠키 발급 | 쿠키를 단 봉투가 은행 → 은행 탭, 쿠키가 보관함으로 떨어짐. **방어 모드:** 열쇠(CSRF 토큰)가 은행 탭 안으로 들어감 | 전체 → 보관함 근접 |
| 3 함정 링크 전송 | 공격자 → 브라우저, 함정 탭이 커지며 등장 | 공격자 쪽 → 브라우저 |
| 4 함정 사이트 접속 | 함정 탭 ↔ 함정 서버 왕복, 이벤트 화면 표시 후 **탭이 뒤집혀 뒷면의 숨은 폼이 드러남** | 함정 서버 → 함정 탭 근접 |
| 5 위조된 송금 요청 | 숨은 폼에서 봉투 출발 → 보관함 앞에서 "목적지 bank.example → 쿠키 자동 첨부" 표시, 쿠키가 봉투에 붙음 → 검문소에서 봉투가 열리고 내용 카드가 나옴. 공격: "쿠키 있음 / 토큰 검사 안 함" → 통과. **방어: "토큰 비어 있음" → 검문소가 방어색으로 바뀌고 403 도장, 봉투가 튕겨 떨어짐(재생 종료)** | 보관함 → 검문소 근접 → 은행 |
| 6 송금 완료 | 금고 문이 열리고 동전이 큰 포물선으로 공격자 섬에 날아감, 잔액이 줄어듦 | 전체(오른쪽으로 치우친) 샷 |

### 꼭 옮길 동작

- **가림 자동 투명:** 매 프레임 카메라 → (카메라 초점, 날아가는 봉투)로 선을 쏴서, 그 선을 막는 물체(탭, 상단바 등)만 불투명도 10%까지 서서히 낮춘다. 가리지 않으면 원래대로 돌아온다. 자유 시점에서도 동작한다.
- **라벨은 HTML:** 행위자 이름, 요청 라벨, 잔액, 검사 목록은 3D 텍스트가 아니라 화면 위 HTML로 띄운다(drei의 `Html` 또는 직접 투영). 글자가 선명하고 테마 토큰을 그대로 쓸 수 있다.
- **봉투·쿠키·열쇠는 항상 카메라를 향한다**(빌보드). 어느 각도에서도 모양이 읽혀야 한다.
- **색은 docs/05 토큰을 쓴다.** 런타임에 CSS 변수(`--attack`, `--defense`, `--neutral`, 면 색 등)를 읽어 재질에 넣고, 테마가 바뀌면 다시 읽는다. 장면 코드에 색 값을 직접 쓰지 않는다.
- **공격·방어 구분:** 공격 단계는 공격색, 차단 순간은 방어색(봉투 날개, 스캔 링, 차단봉, 도장). 색만이 아니라 형태로도 구분한다(도장, 방패·열쇠 모양).

## 3. 데이터 주도 원칙 (용어 = JSON 하나)

3D가 되어도 **용어별로 장면 코드를 따로 쓰지 않는다.** 플레이어가 JSON을 읽어 장면을 만든다.

- 행위자는 **종류(kind)** 로 모양이 정해지고, **구역(zone)** 으로 위치가 자동 배치된다. 좌표를 JSON에 직접 쓰지 않는다.
- 단계의 연출은 정해진 **효과 어휘(effects)** 로만 적는다.
- 카메라는 기본적으로 자동이다. 출발할 때는 봉투를 따라가고, 효과가 일어나는 곳에서는 그 대상을 근접한다. 필요할 때만 `camera` 힌트로 덮어쓴다.

아래는 제안이다. 최종 스키마는 기존 `docs/04` 형식과 호환되게 정하고, 사용자 승인 후 확정한다.

```jsonc
"scene": {
  "actors": [
    { "id": "browser",  "kind": "browser",   "zone": "client" },
    { "id": "bankTab",  "kind": "tab",       "parent": "browser", "site": "bank.example" },
    { "id": "evilTab",  "kind": "tab",       "parent": "browser", "site": "evil.example", "tone": "attack", "appearAt": 3 },
    { "id": "jar",      "kind": "cookieJar", "parent": "browser" },
    { "id": "bank",     "kind": "server",    "zone": "server", "site": "bank.example", "gate": true },
    { "id": "evil",     "kind": "server",    "zone": "server", "site": "evil.example", "tone": "attack" },
    { "id": "attacker", "kind": "attacker",  "zone": "outside" }
  ]
},
"steps": [
  { "title": "세션 쿠키 발급", "from": "bank", "to": "bankTab", "label": "Set-Cookie: session",
    "effects": [ { "type": "storeCookie", "into": "jar" },
                 { "type": "giveToken", "to": "bankTab", "mode": "defense" } ] },
  { "title": "함정 사이트 접속", "from": "evilTab", "to": "evil", "label": "GET /event", "roundTrip": true,
    "effects": [ { "type": "flip", "target": "evilTab", "reveal": "숨은 폼" } ] },
  { "title": "위조된 송금 요청", "from": "evilTab", "to": "bank", "label": "POST /transfer",
    "effects": [ { "type": "attachCookie", "from": "jar" },
                 { "type": "inspect", "at": "bank", "checks": ["cookie", "csrfToken"] } ] }
]
```

확정된 어휘는 `docs/04`의 "3D 장면 필드"가 기준이다(구역 `between`, 경유 `via`, 제자리 단계, 서버·DB 화면판, `attach.note`, 검사 없는 차단의 도장 위치 포함). 아래는 처음 제안할 때의 초안이다.

효과 어휘 초안: `appear`, `flip`, `storeCookie`, `attachCookie`, `giveToken`, `inspect`, `transfer`(동전·데이터가 넘어감), `stamp`(차단 도장, 방어 모드 차단 단계에 자동). 방어 모드의 차단은 지금처럼 `defenses[].blockedAtStep`이 결정하고, 차단 단계에서는 `inspect` 결과가 실패로 바뀐다.

**다른 플레이어 유형** (4단계에서 확정)
- **스택형(콜 스택):** 함수 프레임이 블록처럼 위로 쌓이고, 반환하면 빠진다. 카메라는 쌓이는 높이를 따라 올라간다.
- **점유형(데드락):** 자원은 물체, 스레드는 인물. 자원을 잡으면 손에 들고, 기다리면 줄을 서며, 순환 대기는 바닥에 고리로 표시된다.

## 4. 기술 구성

- `three`, `@react-three/fiber`(React 19에 맞는 버전), 필요하면 `@react-three/drei`(Html 라벨 등). 버전과 API는 context7로 확인한다.
- **PlaybackEngine은 그대로 순수 로직**이다(단계·재생·시작 여부·방어 모드·끝까지 봄 이벤트). 3D 장면은 엔진 상태를 읽어 그리기만 한다.
- 단계 안의 세부 움직임(포물선, 카메라 이동, 뒤집기)은 `useFrame` 기반의 작은 타임라인으로 만든다(시안의 tween 방식). 단계를 넘길 때는 진행 중인 타임라인을 취소하고, 이전 단계까지의 결과 상태를 즉시 적용한 뒤 현재 단계만 재생한다.
- 버튼·탭·자막 같은 일반 UI의 움직임은 계속 Framer Motion을 써도 된다.

## 5. 성능

- 3D 플레이어는 **상세 페이지에서만 동적 import**한다. 홈 번들에 three.js가 들어가면 안 된다.
- `dpr`은 최대 2. 그림자 맵은 1024~1536.
- 화면 밖에 있거나 탭이 숨겨지면 그리기를 멈춘다. 재생이 끝나 움직임이 없으면 필요할 때만 그린다(`frameloop="demand"` 등).
- 노트북 기준 60fps에 가깝게, 휴대폰(375px)에서도 버벅이지 않게 한다.

## 6. 접근성·대체 화면

- **자막만 읽어도 개념이 이해되어야 한다**(NFR-03). 3D는 보조 수단이다.
- 재생 컨트롤, 모드 탭, 자유 시점 버튼은 모두 실제 `button`이다. 자막은 `aria-live="polite"`. 캔버스는 `aria-hidden`이고, 대신 현재 단계 설명이 텍스트로 있다.
- **재생 시작:** 상세 진입 시 1단계 장면 전체를 보여 주고 멈춘다. 무대 가운데의 큰 재생 버튼(실제 `button`, `aria-label="재생"`), 아래 재생 버튼, 스페이스 중 무엇으로 시작해도 1단계 연출부터 끝까지 이어서 재생하고, 가운데 버튼은 사라진다. 단계 사이 대기는 `holdMs()`(`players/stage.ts`): 1.7초 + 자막(제목+본문, 공백 제외) 글자당 50ms, 최소 3초. 연출이 없는 화면(동작 줄이기·2D)은 글자당 100ms.
- **동작 줄이기(`prefers-reduced-motion`):** 똑같이 멈춘 상태로 시작한다. 카메라 이동, 날아가기, 뒤집기 없이 각 단계의 결과 상태로 바로 바뀐다.
- **WebGL을 쓸 수 없을 때:** 단계 목록과 자막만 있는 2D 화면으로 대체한다. 이때도 방어 모드와 차단 단계 표시는 동작해야 한다.
- 자유 시점은 키보드로도 조작할 수 있게 하거나(화살표로 회전), 최소한 끄고 켤 수 있어야 한다.
- CSP는 그대로 둔다. three.js와 R3F는 번들에 포함되므로 `script-src 'self'`로 충분하다. 외부 CDN, `eval`, 인라인 스크립트를 쓰지 않는다.
